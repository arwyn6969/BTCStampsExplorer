## Observed comparison and decision

The reproducible offline import probe is in `probes/reuse_imports.py`; its
results are in `evidence/reuse-imports.json`. Following code edges, the existing
list/card/detail modules reach 224/220/384 local modules, including wallet,
transaction construction, broadcast and database imports. This is a conservative
source graph, not a measurement of executed code or bundle size.

A small leaf-reuse probe executes with no granted runtime permissions. A
restricted Fresh shell in `explorer/` generated a manifest for one route and
built production assets successfully with pinned Deno 2.6.9. The initial build
task accidentally invoked Fresh development mode because it omitted the `build`
argument; the corrected production task exited successfully. Neither legacy
component imports nor its full build task were executed against production.

Select a **thin restricted Fresh surface with leaf reuse**. Preserve the
framework, protocol classifications, identifiers and branding; write two small
display-only pages and one read adapter rather than untangling wallet behavior
from shared cards. Keep this in the owner's application fork as a separate
package, not a separate repository or backend. A framework migration offers no
demonstrated benefit here. There is one production build and one intended
staging pipeline. No second polished application is being built.

Maintenance: shared leaf changes need regression checks; upstream page/card
changes are not automatically inherited. The package must keep its restricted
manifest, runtime permissions and static-only media boundary when updating.

## Data, media and operations

See `evidence/live/` and `evidence/live/data-contract.md` for raw bounded
responses and source comparisons. Samples establish adapter fidelity only. No
preview generation, refresh, signing, broadcast, administration or
business-write route is called.

List/detail GET access works in the observed sample. List numeric flags and
detail boolean flags require explicit normalization; stamp zero is valid.
Quantities need lossless parsing. Detail responses include base64 that the UI
does not consume; reads are bounded. Cache metadata does not prove freshness.
The proof must label freshness unknown and show the source observation time and
reported indexed block.

Existing static raster responses require bounded bytes, MIME/signature and
dimension checks, redirects rejected, and fallback. Active originals remain
unsupported. The predetermined sample covers recent raster, early raster and
HTML sources; it is not a population coverage estimate.

Data and media are operated by the existing Stampchain service. Public reads do
not establish an agreement, quotas, service capacity, support, continuity or
cost. Those remain unknown; no credentials are invented and no replacement
indexer/backend is introduced. Existing deployment scripts default to production
AWS ECS and are not used. No separate Deno-compatible staging account, hostname,
CI, DNS or release access has been verified. Sites hosting runs on Workers and
does not directly host this Deno/Fresh package; changing the runtime just to
bypass missing staging access is outside this decision.
